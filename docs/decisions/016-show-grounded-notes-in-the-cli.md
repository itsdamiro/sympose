# 016 — Show which notes grounded a reply, in the CLI reply header

## Context

Grounding (ADR 014) decides which passages of the user's notes reach the model each turn, and the user could not see that decision. That hides which note the model was handed (a wrong note attached to a follow-up is invisible until the answer is wrong). `run_turn`'s result already carries the grounding hits and the CLI already builds a header per reply (ADR 013 put the model and TTFT there), so this needs no engine change. The measurements that motivated the surrounding work (ADR 015) were taken on Ollama and `gemma2:9b` only; this display is model-independent.

## Decision

The reply header gains one more segment after the TTFT: `@samantha · Gemma2:9b · TTFT 0.8s · from Projects/Atlas.md +2`.

- **What it shows.** The note of the top-ranked passage, and `+N` for the number of other distinct notes grounded on. When nothing matched (including when no vault is configured) the segment is left out entirely. A `no notes` label was built first and removed on review: it reads as a claim about the user's vault, when in most such turns the message simply was not about a note, and when it was about one and nothing was found the reply itself says so.
- **Fitting the line.** The path is cut from the front with an ellipsis only when it does not fit the terminal's remaining width (measured in terminal cells, not characters, since a CJK or emoji filename takes two cells per character), so the filename, the part that identifies the note, is what stays visible: `from …ects/Atlas.md +2`. A path that fits is shown whole. The room is computed from the terminal width at render time; a floor (the whole filename, at most 32 cells, and never under 8) keeps a very narrow terminal from cutting the path to nothing. Below that floor the header runs over and wraps rather than losing the filename; that was a deliberate choice, and dropping the segment in a terminal too narrow for it is the alternative if wrapping proves ugly in use.
- **A knob.** The `show_grounding` setting in `settings_store` (a user-facing default belongs in settings, not a constant), on by default, toggled from the CLI with `/grounding`. Only an explicit `false` turns it off, so a hand-edited or malformed value never silently hides it.
- **Display only.** The header is not stored in the session record and does not change what the model sees. It is not colored differently from the rest of the header: the header is one styled string today, and splitting its styles is a larger change than this needs.

Later slices reuse the same segment: when follow-up grounding rewrites a query, the rewritten query is shown here so a wrong rewrite is visible.

## Consequences

The path is fitted once, when the reply lands, against the terminal's width at that moment and a fixed 4-cell margin for the transcript's own padding: resizing the window afterwards re-wraps the header text but does not re-fit the path, and a change to the transcript's CSS margins would need the margin constant to follow. The display is best-effort and never costs a reply: a hit without a path is skipped. The header is longer, which is why it is fitted to the width and can be turned off. It shows the top note and a count, not every note or the passage text, on purpose: one line beside a reply is a signal, and the full set is a possible later view (the dashboard, or a command that lists the last turn's passages). Only the top note is named, so a reply grounded on several notes shows one path and `+N`; which of the others were used is not visible yet.

**A full line is not the same as a full line already spent (2026-09-28), #28.** `format_grounding`'s floor (the whole filename plus the ellipsis) is meant to accept overflow in a genuinely narrow terminal rather than show an unreadable cut path — a small but positive `room`. It did not distinguish that from `room` that was already zero or negative because the header's other segments (TTFT, the trim notice, the share notices) had already used the whole line before the grounded note was even considered: the floor was forced on top regardless, so a reply header could reach 140+ cells on an ordinary 80-column terminal and wrap. Fixed: `format_grounding` returns `""` when `room <= 0`, leaving the note off the line entirely rather than overflowing it further — the same best-effort tradeoff the rest of this segment already makes, just applied before the floor rather than after it. `header_segment`'s query-squeeze fallback assumed `format_grounding` never returns empty for non-empty hits (it used to fall back to the floor unconditionally); updated to treat an empty squeeze the same as "cannot give up anything." A new test constructs a header where TTFT, both trim-notice lines and both share segments together exceed 80 columns and confirms nothing is appended; confirmed to fail without the fix. The full suite (1722, +1) and ruff stay clean. The residual gap this does not close: the trim and share notices themselves have no width fitting at all, so together they can still reach or pass 80 columns on their own, with nothing after them to omit — accepted for now as the same "the header runs over instead" tradeoff this ADR already makes for a narrow terminal, just not yet extended with matching machinery for those two segments.

**`/grounded`, the full list (2026-09-28), #26.** The header still shows only the top note and a count — this is a separate command, `/grounded`, for "where did that come from, in full." It reads `TurnResult.sent` back exactly as recorded (docs/decisions/025) rather than rebuilding a display from `grounding`: the record and the display can now never drift apart, and it works the same whether the last turn's search ran by meaning, by keyword, or found a note by name or a property value. Each note's line names how it was found (`by meaning`, `named in full`, `by a property value`, or nothing for a plain keyword match) and, for a note found by meaning, its similarity — `sent_record` (ADR 025) now keeps that too, since it did not before. Then, when they happened: an earlier-conversation recap, a follow-up's rewritten query, older turns dropped for space, and a cloud model's sent/withheld categories. `app.last_sent` holds the last completed reply's record — set from `TurnResult.sent`, guarded by the same generation check `session_id` already uses, so a persona switched away from mid-flight cannot overwrite it with a stale one — and survives `/clear`, which wipes the transcript, not this: the record is still true of the last real reply. `None` before any reply this session says so plainly, as does a turn with nothing attached. New tests: `sent_record`'s similarity field (a meaning hit keeps it, a name/value hit does not), `TurnResult.sent` matches exactly what `session.append_turn` persisted, the rendering function on its own (`tests/test_grounded_list.py`), and the command end to end including surviving a `/clear`; each confirmed to fail without its fix. Full suite (1740, +14 net of the schema change fixing one pinned test) and ruff clean. The one thing this does not do: show the passage's actual text. `sent` never holds it, by ADR 025's own design (kept out of the log on purpose), and this command reads the log back rather than re-fetching from the vault — a richer view with the text itself, "as the search bar does," stays open for a web app view, later.

## Not built yet
- **Dim or separate styling for the segment: decided against for now (2026-09-28), #28.** The header is one styled string; splitting its styles needs per-segment `Text` spans, a real rendering change on top of a low-value polish item. Closed as accepted rather than built.
- **Refitting on resize.** The path is fitted once when the reply lands. Still open — revisited but not decided either way in the #28 pass.
- **Width fitting for the trim and share notices.** Neither has any; see "A full line is not the same as a full line already spent" above.
- **The rewritten query: built, as ADR 017 describes** ("The rewrite is visible"). This bullet was stale — noticed and fixed in passing while writing the `/grounded` entry above, unrelated to it.
- **A grounded-note view in the web dashboard.** Waits for the dashboard's chat panel.

## Alternatives rejected

- **A separate line under the header.** Rejected for now: it doubles the vertical space per reply, and the header line has the room when fitted to width.
- **Showing the passage text.** Too long for a line beside a reply; the search bar's result list already shows that shape, and a condensed version of it is what this line is.
- **Always on, no knob.** Rejected: some users will find it noise once they trust the setup.
- **Storing the display string in the session record.** Rejected: the record already keeps the turn; the grounding hits are recomputable from the vault and are not part of what the user said or the model replied. (The premise did not hold up, since the vault and the retriever change: the notes are now recorded, as paths, not as this string; see ADR 025.)
